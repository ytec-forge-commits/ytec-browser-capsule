# 脅威モデル

## 目的と範囲

Y-TEC Browser Capsuleが扱うブラウザープロファイル、保存パスワードCSV、バックアップ、ロールバックを、ローカルWindows環境での盗難、改ざん、誤復元、情報漏えいから保護します。

アプリは現在のWindowsユーザー権限でオフライン動作します。管理者権限、外部通信、テレメトリー、クラウド同期はありません。

## 保護対象

- 保存パスワードCSV
- ブックマーク、履歴、Cookie、セッション、拡張機能設定
- 個人情報を含むプロファイルファイル
- 復元キーファイル、旧形式パスフレーズ、コンテンツ鍵、一時鍵
- バックアップとロールバックの完全性

## 信頼境界

- 既定では現在のWindowsユーザーだけを対象にする。他ユーザーは明示的な表示選択後、現在の権限で読み取れる既知パスだけを対象にする。
- アプリは`asInvoker`で動作し、UAC昇格を要求しない。
- 読み取れない他ユーザー領域はACLを変更せずスキップし、ユーザー名やフルパスをログへ出さない。
- ブラウザー公式UIはアプリ外の信頼境界とし、本人確認や承認を自動化しない。
- バックアップ元ファイル、バックアップ先、復元する`.bvb`は処理中に変化または改ざんされ得る入力として扱う。
- ログ、CI、テストフィクスチャへ実認証情報を持ち込まない。
- 管理者権限を持つ攻撃者と、実行中プロセスメモリを読める攻撃者は非対象とする。

## 脅威と実装済み対策

| 脅威 | 対策 |
| --- | --- |
| バックアップ単体の盗難 | AES-256-GCM、バックアップごとの256-bitランダム鍵。復元キーは別保管を案内 |
| BVB v1のオフライン辞書攻撃 | 8文字以上のパスフレーズとPBKDF2-HMAC-SHA256最低600,000回。新規作成には使用しない |
| ヘッダー、暗号文、tag、マニフェストの改ざん | ヘッダーハッシュとフレームをAADへ含め、GCM認証、ファイルSHA-256、件数／長さ／パス一致を全検証 |
| Path Traversal、UNC、ADS、予約名、大文字小文字衝突 | 正規相対パスだけを許可し、復元ルート境界を再計算 |
| リパースポイントによる読取・上書き逸脱 | 検出、計画、展開、適用の各境界で追跡せず拒否 |
| 他Windowsユーザー領域の過剰探索 | 既定OFF、明示選択、ローカル既知パス限定、現在権限の読み取りプローブ、アクセス不能時スキップ |
| 平文CSVの別ユーザー閲覧 | 現在ユーザーとSYSTEMだけの保護ACL、安定検出、即時一時暗号化、削除失敗警告 |
| CSV内容の漏えい | 値を保持、表示、ログ出力せず、ヘッダーと件数だけをストリーミング検証 |
| 認証情報DBへの危険なアクセス | 共通の保護ファイル規則でバックアップから除外し、復元とCSV抽出の選択プロファイルでも成分種別に関係なく拒否。適用側は書込前にWindows短縮名の実効パスも検査し、公式CSV方式だけを使用 |
| ブラウザー起動中の不整合 | 通常終了を先に依頼し、明示確認後だけ現在セッション・完全パス一致の対象を強制終了。開始前・適用中に再確認し、別ユーザーや確認不能プロセスは操作せず安全側で実行中扱い |
| 誤ったプロファイルへの復元 | ブラウザー間割当を禁止し、同名でも自動確定せず、1対1の明示対応を要求 |
| 別PC／別ユーザーへの端末依存データ復元 | 環境ID不一致は移行モードを既定とし、Cookie、セッション、パスキーの非保証を警告 |
| 復元失敗による既存データ破損 | 復元前に暗号化ロールバックを作成・完全検証し、失敗時は自動適用。新規作成ファイルも除去 |
| 一部だけ検証された復元 | `.bvb`全体の認証完了後、選択エントリーだけを展開し、適用前後のSHA-256を確認 |
| 巨大入力、ファイル数攻撃 | エントリー100,000件、マニフェスト16MiB、個別64GiB、合計2TiB、PBKDF2上限20,000,000回 |
| UI進捗による過負荷 | バックアップ／復元進捗を約10回／秒へ抑制 |
| クラッシュ後の一時データ | CSVセッションは次回起動時にGUID配下だけを清掃。暗号化作成失敗は`.partial`を削除 |
| 設定による外部通信・秘密保存 | 設定は既定バックアップ先だけ。UNC／デバイスパスを拒否し、復元キー、パスフレーズ、認証情報、ブラウザーデータを保存しない |

## 禁止する実装

- Chrome / Edgeの認証情報データベースの読取、解析、直接復号
- Firefoxの認証情報ファイルからの抽出
- DPAPIまたはApp-Bound Encryptionの回避
- ブラウザーへのコード注入
- 本人確認、CSVエクスポート／インポート承認の自動操作
- 平文の集約ZIPまたはプロファイルアーカイブ
- 検証済みロールバックなしの既存プロファイル上書き
- 管理者権限、外部通信、テレメトリー

`SecurityTests`は、本体ソースに禁止能力を示す断片がないこと、本体に外部NuGetパッケージがないこと、危険なパスや改ざん入力を拒否することを継続確認します。文字列検査はレビューの代替ではありません。

## 残余リスク

- ファイルシステム検査は時点ごとの検査であり、検査と書込の間の同一ユーザープロセスによる競合を原子的に封じるものではない。保護ファイルの通常名はロールバック・展開前、短縮名は適用前に拒否する。
- 汎用の`RestoreFileOperation`でブラウザー情報がない呼出しは従来のパス検査を維持する。現行アプリの復元・ロールバック操作はすべて信頼済み復元先の`BrowserId`を渡す。新たな呼出し元でもこの境界を維持する必要がある。
- 管理者／カーネル権限、キーロガー、侵害済みブラウザー、実行中メモリ読取は防げない。
- `.bvb`と`.ybckey`が一緒に盗まれた場合、バックアップの秘密性は保護できない。
- BVB v1では弱いパスフレーズの保護強度を保証できない。
- SSD上で削除した平文CSVの物理的完全消去は保証しない。
- 独自配置のブラウザー実行ファイルでは実行中判定ができない場合がある。
- フル復元は安全なオーバーレイであり、バックアップにない既存ファイルを削除しない。
- Cookie、セッション、パスキーなど端末・ユーザーに結び付くデータは別環境で動作しない場合がある。
- 他Windowsユーザーの保存パスワードCSVは、そのユーザーでサインインして公式画面から別途扱う必要がある。
- 一時領域の削除失敗時は警告または次回清掃に委ねる。強制削除や権限昇格は行わない。
- 1.0.0までの実ブラウザー・クリーンVM・公式CSV・アクセシビリティ
  受け入れ記録は履歴として有効です。1.2.0で追加した日英UI、設定schema v2、
  日英PDF、公開OSS用の秘密情報・鍵スキャンは別途1.2.0の回帰確認対象です。

## 公開repositoryと署名鍵

- `.ybckey`、`.bvb`、保存パスワードCSV、`.pfx`、`.p12`、`.pem`、`.key`、
  `.snk`はGit追跡対象にしない。
- 公開前に現在の作業ツリーだけでなくGit全履歴を検査し、秘密鍵形式、
  代表的なクラウド／GitHub token形式、秘密ファイル拡張子を検出した場合は
  公開を中止する。
- 復元キーはバックアップごとにOSの暗号学的乱数生成器から作り、固定鍵、
  共有マスターキー、復旧用バックドアを設けない。
- Authenticode秘密鍵は既存の承認済み署名境界から取り出さず、repository、
  GitHub Secrets、CI Artifact、ローカルバックアップへ保存しない。
- 公開ZIPは別途展開して、禁止拡張子、PDB、実データ、秘密値、ハッシュ一覧の
  不整合がないことを確認する。
- 設定ファイルには利用者が選んだローカルフォルダーのフルパスが
  平文で含まれる。現在ユーザーのLocalAppData内だけで扱い、
  ログやバックアップマニフェストへ転記しない。
