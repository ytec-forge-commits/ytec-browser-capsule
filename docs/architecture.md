# アーキテクチャ

## 対象と状態

Y-TEC Browser Capsule `1.2.1`は、Windows 10 / 11 x64、.NET 10、WPFで動作するローカル専用アプリです。Chrome Stable、Edge Stable、Firefox Stable / ESRの検出、BVB v2復元キー方式、公式CSV補助、検証済み復元、ロールバック、日本語／英語UIまでを実装しています。

アプリ本体は外部NuGetパッケージを使わず、標準ライブラリだけで構成します。管理者権限、外部通信、クラウド、テレメトリー、認証情報データベース解析はありません。他Windowsユーザーの検出は既定OFFで、現在の権限から読み取れるローカル既知パスだけを対象にし、アクセス不能領域をスキップします。

実画面付きの`操作マニュアル.pdf`と`Operation Manual.pdf`を配布フォルダーへ
同梱し、メイン画面のマニュアルボタンから現在のUI言語に対応するPDFを
既定のPDF閲覧アプリで開きます。外部URLへ接続せず、実行ファイルと同じ
フォルダーの固定ファイル名だけを参照します。

`WindowsUserProfileCatalog`はWindowsのローカルプロファイル一覧を読み取り、SIDまたはプロファイルパスを一方向ハッシュ化した安定識別子だけをブラウザー検出へ渡します。Chrome／Edge／Firefoxの各ソースは1ブラウザーにつき複数のWindowsユーザースコープを集約し、所有者付きの一意なInstallationId／ProfileIdを生成します。所有者の表示名と安定識別子は平文ヘッダーへ入れず、暗号化マニフェスト内にだけ保存します。

保存パスワードCSVの公式画面補助は現在ログイン中のWindowsユーザーだけに制限します。別ユーザー分は、そのユーザーでサインインして公式画面を使う必要があります。また、バックアップ元と復元先の所有ユーザー安定識別子が異なる場合、同一PCでも復元サービスが移行モードへ切り替えます。

## 依存方向

```text
Domain
  ↑
Application ← Infrastructure
  ↑              ↑
Browsers.Common  │
  ↑              │
Browsers.Chromium│
  ↑              │
Chrome / Edge    │
Browsers.Firefox │
       ↑         │
         WPF App
```

| プロジェクト | 責務 | 許可する内部参照 |
| --- | --- | --- |
| Domain | モデル、契約、例外、安全なエントリーパス | なし |
| Application | 検出、バックアップ、復元、ロールバックのオーケストレーション | Domain |
| Infrastructure | Windowsプロセス照合、環境ID、AES-GCMコンテナ、CSV一時保護、安全なファイル適用 | Application、Domain |
| Browsers.Common | 安全なファイル列挙、バックアップ計画、パス変数展開 | Domain |
| Browsers.Chromium | ポリシー、標準パス、`Local State`、フォールバック | Browsers.Common |
| Browsers.Chrome | Chrome Stableの構成 | Browsers.Chromium |
| Browsers.Edge | Edge Stableの構成 | Browsers.Chromium |
| Browsers.Firefox | Firefox Stable / ESRのINI解析、フォールバック、計画 | Browsers.Common |
| App | WPF UI、ダイアログ、依存の手動構成 | Application、Infrastructure、各ブラウザー |

`IntegrationTests`は`.csproj`を検査して依存方向、x64、WPF、`asInvoker`を固定します。規模が外部DIを必要とするまでは、Appでの明示的な手動構成を維持します。

## バックアップ

1. 現在ユーザーの既知ブラウザー／プロファイルだけを検出する。
2. ユーザーがプロファイルとコンポーネントを選ぶ。
3. 対象ブラウザーが起動中なら通常終了を依頼する。残存時はユーザー確認後、現在セッションかつ実行ファイル完全パス一致の対象だけを強制終了する。
4. 許可リストまたはフルプロファイル規則から固定計画を作る。
5. キャッシュ、ロック、一時ファイル、保護対象の認証情報データベース名、リパースポイントを除外する。
6. 256-bitランダム鍵を`.ybckey.partial`へ書き、平文ZIPを作らず`.bvb.partial`へ直接暗号化する。
7. 完成候補を復元キーで完全検証し、成功後だけ`.ybckey`と`.bvb`へ切り替える。

進捗は最大約10回／秒へ抑え、ファイル全体をメモリに載せません。元ファイルの長さ／更新日時が計画後に変わった場合は中止します。

## 保存パスワードCSV

アプリはブラウザー内部の認証情報を読みません。プロファイルを明示して公式のパスワード管理画面を開き、ユーザー本人がCSVをエクスポートします。標準画面を開いた時点から専用フォルダーを自動監視するため、保存後に追加操作は原則不要です。

- セッションごとにランダム名のACL制限フォルダーを作成
- ファイルが安定し排他読取できるまで待機
- UTF-8と必須ヘッダーだけをストリーミング検証
- 値を保持、表示、ログ出力しない
- ランダムなメモリ内一時鍵で即時AES-GCM暗号化
- 平文CSVを削除し、失敗時だけパスをユーザーへ警告
- `.bvb`へはプロファイルIDと固定名`passwords.csv`で格納し、元ファイル名を保存しない
- 復元時は選択したCSVだけをACL制限領域へ一時復号し、公式UIでの取込後に削除

## 復元

1. `.bvb`全体を認証・ハッシュ検証する。
2. バックアップ元と同じブラウザーの復元先をユーザーが明示選択する。
3. 環境IDが違う場合は別環境移行を既定とする。
4. プロファイルへ書き込む場合は、対象ブラウザーを終了確認する。
5. 現在の復元先を暗号化`.bvb`と専用`.ybckey`のロールバックへ保存・自己検証する。
6. 選択したコンポーネントだけを復元先と同じボリュームの一時領域へ展開する。
7. 各ファイルを隣接一時ファイルへコピーし、長さ／SHA-256検証とディスクflush後に原子的に置換する。
8. 途中失敗やキャンセルではロールバックを適用し、失敗した復元が新規作成したファイルも削除する。

フル復元は安全なオーバーレイです。バックアップにない既存ファイルを一括削除しません。保護対象の認証情報データベースはバックアップにも復元にも含めません。保存パスワードCSVはプロファイルへ直接書き込まず、公式UIでのみ取り込みます。

2026-09-29の再公開候補では、Domainの単一の保護対象設定をバックアップと復元で共有します。認証済みBVBも作者由来の入力として扱い、対象プロファイルの保護対象名をcomponentに関係なく、ロールバック・展開前に拒否します。CSV取り出しとロールバック適用にも同じ検査を使います。最終適用ではWindowsの実効ファイル名を解決し、短縮名経由も書き込み前に拒否します。これは同一ユーザーの同時ファイル置換を原子的に防ぐ保証ではありません。

## 実行と配布

- ライブラリ: `net10.0`
- WPF: `net10.0-windows`、`win-x64`
- 実行レベル: `asInvoker`
- 同一Windowsセッションでは名前付きMutexにより単一起動
- 配布: x64自己完結型ポータブルフォルダー／ZIP
- 永続設定: `%LOCALAPPDATA%\Y-TEC\BrowserCapsule\settings.json`
  （schema v2、既定バックアップ先と言語だけを原子的に置換。schema v1は
  保存先を維持して`SystemDefault`へ移行）
- 一時CSV: `%LOCALAPPDATA%\Y-TEC\BrowserCapsule\Staging`
- ロールバック: `%LOCALAPPDATA%\Y-TEC\BrowserCapsule\Rollbacks`
- ログ: 実装しない。秘密を含み得る診断ログを自動生成しない

Release生成後は`eng/Test-PortableRelease.ps1`がフォルダーとZIPを
別々に全件ハッシュ照合し、必須ライセンス・notice・操作文書、
FileVersion、PDB非同梱、Authenticode状態を検査します。一般公開版は
承認済みの既存Y-TEC自己署名を使い、最終Y-TEC EXE・DLLの署名者、署名の
完全性、有効期間、タイムスタンプを別途検証してから最終ZIPを封印します。
自己署名のルート非信頼だけを明示した条件で区別し、改ざんや想定外の結果は
拒否します。全ファイルSHA-256とZIP sidecarの一致を必須とし、秘密鍵を
repository、GitHub Secrets、ローカルPFXへ出力しません。
詳細は[コード署名方針](../CODE_SIGNING.md)を正本とします。

## テスト境界

- UnitTests: 検出、INI／JSON、パス、バックアップ規則、CSV構文、KDF、公式画面起動引数
- IntegrationTests: 依存構造、各2件・計6プロファイルの3ブラウザー混在バックアップ、6つの明示ターゲットへの一本通し復元、CSV組込、複数対応付け復元、環境差、ロールバック
- SecurityTests: 禁止能力、外部依存、暗号改ざん、選択展開、ACL、一時暗号化、Path Traversal、ハッシュ不一致

すべて合成フィクスチャを使い、実認証情報はテストへ持ち込みません。実ブラウザーの最終受け入れ確認は[手動テスト計画](manual-test-plan.md)で管理します。

利用者向け例外はApplication層の`UserFacingErrorMapper`で安定した
エラーコードへ変換し、WPF層で日本語または英語の安全な説明へ変換します。
予期しない例外本文や完全パスをUIへ渡しません。
WPFのアクセシブル名、Tab移動、ライブリージョンはIntegrationTestsで
静的に検査し、実際の支援技術確認は手動受け入れ項目として残します。

利用者設定の契約はDomain、JSON保存はInfrastructureに分離します。
設定ファイルへ秘密は保存せず、ローカルの完全修飾パスだけを
既定バックアップ先として許可します。安全性に直結する完全検証、
キャッシュ除外、CSV一時領域清掃、フルパス非表示は利用者が
誤って無効化できない固定動作です。
