# ADR 0004: BVB v2復元キーと案内型ワークフロー

## 状態

採用。Y-TEC Browser Capsule 1.1.0から適用。

## 背景

別PCへの移行が主用途であり、長いパスフレーズの作成・確認入力・再入力は
安全ではあるものの負担が大きいという実利用結果が得られました。また、
ブラウザーを通常終了してもバックグラウンドプロセスが残り、処理失敗に
なることがありました。公式CSVも保存先の指定と取り込み開始の二重操作が
分かりにくい状態でした。

## 決定

- 新規バックアップはBVB v2と256-bitランダム鍵入り`.ybckey`を作成する。
- 復元は`.bvb`と対応する`.ybckey`を選択する。
- BVB v1はパスフレーズによる読み取り・復元だけを維持する。
- 固定のアプリ鍵、平文バックアップ、パスワードなしモードは設けない。
- キーは秘密情報であり、同一フォルダー保存時は盗難リスクを警告する。
- ブラウザーは通常終了を先に依頼し、残存時だけユーザーの明示確認後に
  現在セッション・完全パス一致の対象プロセスを強制終了する。
- 公式CSV画面での本人確認・承認・エクスポート・インポートは自動化しない。
  保存先フォルダーの自動監視、安定確認、即時一時暗号化だけを自動化する。
- 復元用CSVでクリップボードへ渡すのはCSVファイルではなくフォルダーパス
  とし、CSV関連付けアプリの誤起動を防ぐ。

## 結果

別PC移行は2ファイル選択になり、文字列秘密の作成・記憶・入力が不要に
なります。一方、`.ybckey`を失うと復元できず、`.bvb`と一緒に盗まれた
場合は暗号化保護が成立しません。このためUIとマニュアルで分離保管を
案内し、キー値は画面・ログ・マニフェストへ出しません。
