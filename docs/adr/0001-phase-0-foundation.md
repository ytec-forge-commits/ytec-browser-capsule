# ADR-0001: Phase 0の.NET 10 / WPF基盤

- 状態: 採用
- 日付: 2026-07-24
- 対象: Phase 0

## 文脈

Windows x64向けWPFアプリを、ブラウザー固有処理、Windows実装、ユースケース、ドメインから分離して段階的に開発する必要があります。セキュリティ上重要な処理は後続フェーズでテスト主導にし、Phase 0で実装してはいけません。

## 判断

- .NET SDK 10.0.302、WPF、C#を使用する。
- 仕様書どおり9本体プロジェクトと3テストプロジェクトへ分割する。
- Nullable、SDKアナライザー、TreatWarningsAsErrors、x64を共通設定にする。
- WPFは`asInvoker`で起動する。
- 本体の外部NuGet依存は0件とし、DI、ログ、暗号ライブラリをまだ追加しない。
- テスト基盤だけに`Microsoft.NET.Test.Sdk`、`xunit`、`xunit.runner.visualstudio`を追加する。
- 依存バージョンは`Directory.Packages.props`で一元管理する。
- Phase 0時点では製品名を未確定、アセンブリを`0.0.0`とする。正式名称の決定はADR-0002で記録する。

## 標準ライブラリだけでは不足する理由

.NET SDKはテストホストとテストフレームワークをアプリ標準ライブラリとして提供しません。`dotnet test`でテストを検出・実行し、アサーションを記述するため、テストプロジェクトに限って次を使用します。

- `Microsoft.NET.Test.Sdk`（MIT）: VSTestホスト
- `xunit`（Apache-2.0）: テストフレームワーク
- `xunit.runner.visualstudio`（Apache-2.0）: VSTestアダプター

いずれも商用利用と再配布が認められるライセンスで、`PrivateAssets`を適用できるランナーは本体へ伝播させません。

## 影響

- DomainとApplicationはWPFへ依存しない。
- ChromeとEdgeはChromium共通層を共有し、Firefoxは独立アダプターにできる。
- Appが構成ルートとして具象プロジェクトを参照する。
- Phase 1以降で依存方向を破る変更は統合テストが検出する。
- DIやログの外部パッケージが必要になった場合は、標準ライブラリで不足する理由、脆弱性、ライセンス、戻し方を別ADRでレビューする。

## 採用しなかった案

- Phase 0で暗号、ブラウザー検出、CSV処理の型や実装を先行作成する案: フェーズ境界を越えるため採用しない。
- 本体へ汎用DI／ログパッケージを追加する案: 現時点では必要性を証明できないため採用しない。
- WPFとドメインを単一プロジェクトにする案: テスト独立性とブラウザーアダプター分離を損なうため採用しない。
