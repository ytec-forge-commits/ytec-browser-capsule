# ADR 0009: 日英UI、設定schema v2、公開OSS運用

- 状態: Accepted
- 日付: 2026-08-25

## Context

Y-TEC Browser CapsuleをY-TEC ForgeとGitHubで一般公開し、日本語利用者と英語利用者の両方へ、安全境界と復元キーの扱いを同じ精度で伝える必要がある。既存の`settings.json` schema v1には既定バックアップ先が保存されているため、言語追加で値を失ってはならない。

また、公開repositoryへ復元キー、署名鍵、トークン、実ブラウザーデータが混入すると回収が困難になる。

## Decision

- UI言語は`SystemDefault`、`Japanese`、`English`の3値とする。
- 設定schemaをv2へ上げ、v1読込時は既定バックアップ先を維持して言語を`SystemDefault`へ移行する。
- 言語変更は設定保存後の再起動で適用する。実行途中のダイアログだけが別言語になる状態を作らない。
- 日本語・英語PDFをポータブルZIPへ同梱し、選択言語に対応するPDFをアプリから開く。
- 本体の外部NuGet依存は追加せず、WPF標準機能とローカル翻訳辞書で実装する。
- `.ybckey`を含む秘密ファイル拡張子をGit除外し、公開前CIで現在のファイルとGit全履歴を検査する。
- コード署名の秘密鍵はrepositoryやGitHub Secretsへ置かず、承認済みの署名管理境界から取り出さない。2026-09-29の再公開では既存Y-TEC自己署名を使い、現在の運用正本は`CODE_SIGNING.md`とする。

## Consequences

- v1利用者の既定バックアップ先は移行後も維持される。
- 言語追加時は日本語・英語の静的文言、動的文言、アクセシビリティ名、マニュアルを同時に更新する必要がある。
- 実行時依存とライセンスは増えない。
- CI時間はGit履歴の秘密情報・鍵スキャン分だけ増えるが、公開後に秘密を回収するリスクを下げられる。
