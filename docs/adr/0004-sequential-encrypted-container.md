# ADR-0004: シーク不要の逐次暗号化コンテナ

- 状態: 採用
- 日付: 2026-07-24

## 背景

平文ZIPを作らずに`ZipArchive`を暗号ストリームへ直接書くことは可能ですが、読取時にシークが必要となる構成では暗号チャンク索引とランダムアクセス復号が必要です。Phase 2では、改ざん耐性とストリーミング性を小さな実装面積で検証できる形式が必要です。

## 決定

1. ZIPではなく、圧縮なしの独自逐次エントリーコンテナを採用する。
2. 暗号は.NET標準のAES-256-GCM、鍵導出はPBKDF2-HMAC-SHA256を使用し、独自暗号を作らない。
3. 4 MiBの既定チャンクごとに認証し、乱数prefixと単調増加番号からnonceを構成する。
4. 平文ヘッダー全体のSHA-256とフレームヘッダーをAADに含める。
5. 最終フラグ付きチャンクを必須にし、欠落・重複・順序変更・末尾追加を明示的に拒否する。
6. 各エントリーは長さを先に持ち、内容直後のSHA-256と暗号化マニフェストのSHA-256を照合する。
7. `.partial`を閉じたあと同じサービスで全体を再読取検証し、成功時だけ完成名へ移動する。
8. パスフレーズ一時バイト列、派生鍵、平文作業バッファを使用後にゼロ化する。
9. 復号ストリームはシークを提供しない。復元時は検証済み一時領域へ逐次展開し、全体成功前のデータを本番プロファイルへ適用しない。

## 影響

- コンテナはZIPツールでは開けない。
- Phase 3以降のバックアップは、エントリーの宣言長を固定してから開始する必要がある。
- 圧縮を行わないため、キャッシュ除外と空き容量見積もりが重要になる。
- 復元は安全なステージング領域を必要とするが、暗号化ストリーム自体にシーク索引を持たせる必要がない。
- フォーマットの詳細は`docs/backup-format.md`を正本とする。
